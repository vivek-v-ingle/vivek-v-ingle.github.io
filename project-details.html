VILMA — Visual Imitation Learning

VILMA (Visual Imitation Learning Mimicking Agent) is the visual imitation learning module developed within the I-Genius project for the ARISE ecosystem.

The system enables robot manipulation skills to be generated from human demonstrations. Instead of manually programming every robot motion, the pipeline processes visual demonstrations, extracts hand and object trajectories, generates reusable robot skills, and prepares the resulting trajectory for robot execution.

The implementation is designed as a reusable, local-first robotics module rather than as a robot-specific application. The reusable workflow covers visual demonstration processing, trajectory extraction, DMP-based skill generation, skill reuse, trajectory preview and ROS 2/Vulcanexus delivery.

Human Demonstration

The pipeline begins with a human demonstrating a manipulation task. Demonstration data can be provided through supported visual inputs including ZED SVO/SVO2 recordings, RGB-D data and video-based workflows.

The purpose of this stage is to capture the motion information required to reproduce a manipulation skill without manually specifying the complete robot trajectory.

Hand Perception

Human hand motion is extracted from the demonstration using visual hand landmark detection.

  • MediaPipe Hands
  • 21 3D landmarks per detected hand
  • Frame-by-frame hand trajectory extraction

Object Perception

Objects involved in the manipulation task are detected and tracked throughout the demonstration.

  • Ultralytics YOLO
  • Object bounding boxes and confidence scores
  • BoT-SORT multi-object tracking
  • Stable object trajectories

RGB-D & SVO Processing

VILMA supports visual demonstration processing from recorded RGB-D data. For ZED-based demonstrations, SVO/SVO2 recordings can be converted into an RGB-D representation containing RGB frames, depth maps and camera information.

This allows the perception and trajectory-generation stages to be developed and evaluated using recorded demonstrations without requiring continuous access to the physical robot.

Trajectory Extraction

The detected hand and object information is transformed into structured motion trajectories. These trajectories provide the connection between the visual demonstration and the robot skill representation.

The resulting processing produces trajectory data, visualisation plots and intermediate artifacts that can be inspected before the trajectory is sent toward robot execution.

Dynamic Movement Primitives

Demonstrated motion can be represented using Dynamic Movement Primitives (DMPs), providing a reusable representation of the learned movement.

This allows the demonstrated motion to be treated as a robot skill rather than as a single fixed recording.

Skill Reuse

The Skill Reuse workflow allows generated trajectories to be adapted to a new object or target configuration.

The adapted trajectory can then be previewed and exported before being delivered to the robot-side execution environment.

ROS 2 / Vulcanexus Robot Communication

Once a trajectory has been generated and validated, VILMA can deliver it through ROS 2 and Vulcanexus. The communication layer separates the imitation learning system from the hardware-specific robot controller.

The documented trajectory interface publishes a geometry_msgs/msg/PoseArray on the /learned_trajectory ROS 2 topic.

The transport uses ROS 2 with DDS, with the documented implementation using the Fast DDS middleware.

Edge Receiver

On the edge side, the generated trajectory is received by a reusable ROS 2 receiver. The receiver can persist the trajectory and associated metadata before handing it to the robot-specific execution backend.

Robot Integration

The reusable VILMA module is intentionally separated from vendor-specific robot control. Physical execution depends on the target robot SDK, calibration, communication configuration and safety validation.

ARISE Experiment — I-Genius

VILMA forms the visual imitation learning component of the I-Genius experiment within the ARISE ecosystem. Its role in the demonstrator covers perception, imitation learning and robot trajectory generation.

The ARISE integration demonstrates how a reusable visual imitation-learning module can operate within a distributed robotics architecture using ROS 2, Vulcanexus and DDS-based trajectory communication.

The architecture also provides an integration boundary for FIWARE / NGSI-LD context and execution metadata, while the robot trajectory remains on the ROS 2 communication path.

Scope & Limitations

The reusable module separates general visual imitation-learning functionality from demonstrator-specific hardware integration.

  • Physical robot execution requires the target robot SDK and communication interface.
  • Camera placement and recording conditions are deployment-specific.
  • Robot-camera calibration is specific to the physical deployment.
  • Physical safety validation remains outside the generic reusable module.

Project Overview

This master's thesis focused on the design and implementation of a robotic mirror-therapy system combining virtual reality, a VR exergame and a bimanual robotic exoskeleton.

The project investigated mirror-based haptic feedback within a virtual-reality rehabilitation environment and evaluated user performance during the developed exergame.

The work was carried out at the ARIES Lab under the supervision of Professor Lorenzo Masia.

Research Lab: ARIES Lab — Lorenzo Masia

Experimental Evaluation

The developed VR exergame was evaluated using different difficulty levels and two haptic-feedback conditions: normal haptic feedback and mirror haptic feedback.

Results

The experimental evaluation compared participant performance between normal and mirror haptic feedback conditions across the different game levels.

The results showed higher mean scores for the mirror-feedback condition across the evaluated levels.

Project Overview

The goal of this project is to develop a distributed architecture for accurately identifying Activities of Daily Living (ADLs) from recorded inertial sensor data.

The system uses data collected from six Inertial Measurement Units (IMUs) positioned on different parts of the body. The recorded measurements provide temporal information about body movement that can be used to learn and recognise different daily activities.

The project focuses on machine learning-based activity recognition using multimodal IMU data rather than camera-based information.

View Dataset

Dataset

The dataset contains measurements from six IMUs placed on the volunteer's back, left lower arm, left upper arm, right lower arm, right upper arm and right thigh.

Nine Activities of Daily Living were recorded:

  • Walking
  • Sitting down
  • Standing up
  • Opening a door
  • Closing a door
  • Pouring water
  • Drinking using a glass
  • Brushing teeth
  • Cleaning the table

Two distinct activity sequences were designed and both were performed twice, once using only the right hand and once using only the left hand.

Multi-IMU Sensor Data

Each IMU records measurements describing the movement of the corresponding body segment.

The sensor CSV files contain a data-type label, timestamp, four quaternion components, three acceleration components and three angular velocity components.

The measurements were recorded with a sampling interval of approximately 30 milliseconds, providing a temporal representation of the performed activities.

Activity Annotation

Separate annotation CSV files provide the temporal boundaries of the recorded activities.

The annotations identify activity scopes including Both Arms, Right Arm, Left Arm and Locomotion, together with timestamps indicating when an activity starts and ends.

Session identifiers distinguish the different experimental sequences.

Machine Learning

The project treats Activities of Daily Living recognition as a supervised machine learning problem based on temporal inertial sensor data.

The distributed architecture processes the recorded sensor streams and associates the measurements with their corresponding annotated activities. These labelled sequences can then be used to learn activity-specific movement patterns and distinguish between different daily activities.

The approach focuses on learning from multiple body-mounted sensors rather than relying on visual observations.

My Contribution

The project involved working with multimodal IMU data, activity annotations and the distributed architecture required for Activity of Daily Living recognition.

The work involved understanding the structure of the sensor dataset, handling temporal activity annotations and developing the machine learning pipeline required to identify activities from inertial measurements.

Experimental Data

Videos were recorded during the experiments but were used only for activity labelling purposes. The videos are not part of the published dataset.
